//=== Extreme Networks

PacketFence supports Extreme Networks switches using:

[options="compact"]
* linkUp/linkDown
* MAC Address Lockdown (Port Security)
* Netlogin - MAC Authentication
* Netlogin - 802.1X
* Netlogin - web authentication
* RADIUS authentication for CLI access

Don't forget to save the configuration!

==== All Extreme XOS based switches

In addition to the SNMP and VLANs settings, this switch needs the Web Services
to be enabled and an administrative username and password provided in its
PacketFence configuration for Web Services.

==== Extreme EXOS v30.x

This switch version module is designed for Extreme switch series utilizing
Extreme versions v30.x
Note: "EXOS v30.x" module is tailored for the switch series operating on Extreme
versions v30.x. Furthermore, it inherits all functionalities from the existing
"EXOS" module, making all the configurations below applicable to EXOS v30.x.

===== MAC Address Lockdown (Port-Security)

linkUp/linkDown traps are enabled by default so we disable them and enable MAC
Address Lockdown only.

Global config settings without Voice over IP (VoIP):

  enable snmp access
  configure snmp add trapreceiver 192.168.1.5 community public
  enable web http
  configure vlan "Default" delete ports <portlist>
  configure vlan registration add ports <portlist> untagged
  configure ports <portlist> vlan registration lock-learning
  disable snmp traps port-up-down ports <portlist>

`<portlist>` = ports to secure (individual port or port-range with dash).

Global config settings with Voice over IP (VoIP):

  enable snmp access
  configure snmp add trapreceiver 192.168.1.5 community public
  enable web http
  configure vlan "Default" delete ports <portlist>
  configure vlan registration add ports <portlist> untagged
  configure vlan voice add ports <portlist> tagged
  configure ports <portlist> vlan registration lock-learning
  configure ports <portlist> vlan voice limit-learning 1
  disable snmp traps port-up-down ports <portlist>

`<portlist>` = ports to secure (individual port or port-range with dash).

===== CoA configuration

Starting from version EXOS 22.1 CoA is supported.

  configure radius dynamic-authorization 1 server 192.168.1.5 client-ip 10.0.0.8 vr VR-Default shared-secret useStrongerSecret
  enable radius dynamic-authorization

===== MAC Authentication

SNMP configuration

  enable snmp access snmp-v1v2c
  configure snmp add community readonly public
  configure snmp add community readwrite private

AAA Configuration

  configure radius netlogin primary server 192.168.1.5 1812 client-ip 10.0.0.8 vr VR-Default
  configure radius netlogin primary shared-secret useStrongerSecret
  enable radius netlogin

Netlogin (MAC Authentication)

  configure netlogin vlan temp
  enable netlogin mac
  configure netlogin add mac-list default
  configure netlogin dynamic-vlan enable
  configure netlogin dynamic-vlan uplink-ports 50
  configure netlogin mac authentication database-order radius
  enable netlogin ports 1-48 mac
  configure netlogin ports 1-48 mode port-based-vlans
  configure netlogin ports 1-48 no-restart

===== 802.1X

SNMP configuration

  enable snmp access snmp-v1v2c
  configure snmp add community readonly public
  configure snmp add community readwrite private

AAA Configuration

  configure radius netlogin primary server 192.168.1.5 1812 client-ip 10.0.0.8 vr VR-Default
  configure radius netlogin primary shared-secret useStrongerSecret
  enable radius netlogin

Netlogin (802.1X)

  configure netlogin vlan temp
  enable netlogin dot1x
  configure netlogin dynamic-vlan enable
  configure netlogin dynamic-vlan uplink-ports 50
  enable netlogin ports 1-48 dot1x 
  configure netlogin ports 1-48 mode port-based-vlans
  configure netlogin ports 1-48 no-restart
  configure netlogin mac ports 1-48 timers reauth-period 86400 reauthentication on
  configure netlogin dot1x ports 1-48 timers server-timeout 10 reauth-period 84600


==== MAC Authentication + 802.1x

You can mix the MAC Authentication and 802.1X on the same switchport. If the
device fails 802.1X authentication, it will fallback to the MAC Authentication.
Configure the MAC Authentication and 802.1x like the section above and add this
extra command:

  enable netlogin ports 1-48 dot1x mac


===== Policy based access

Assign switch-defined policies via PacketFence.

Define switch policy:

  configure policy profile 1 name "gaming" pvid-status "enable" pvid 3521 untagged-vlans 3521
  configure policy profile 2 name "guest" pvid-status "enable" pvid 3522 untagged-vlans 3522
  configure policy maptable response both
  configure policy vlanauthorization enable

Enable 'Role by Switch Role' in PacketFence switch configuration; assign
policies to roles. Policies returned in Filter-Id attribute.

Use 'Extreme EXOS' switch type for this feature.

===== Web authentication

SNMP configuration

  enable snmp access snmp-v1v2c
  configure snmp add community readonly public
  configure snmp add community readwrite private

AAA Configuration

  configure radius netlogin primary server 192.168.1.5 1812 client-ip 10.0.0.8 vr VR-Default
  configure radius netlogin primary shared-secret useStrongerSecret
  enable radius netlogin

Web-auth profile

  configure dns-client add name-server 8.8.8.8 vr VR-Mgmt
  configure dns-client add domain-suffix example.com
  configure policy captive-portal web-redirect 1 server 1 url http://192.168.1.5:80/Extreme::EXOS enable
  configure policy profile 4 name "Unregistered" pvid-status "enable" pvid 0 web-redirect 1
  configure policy rule 4 ipdestsocket 192.168.1.5 mask 32 forward
  configure policy rule 4 udpdestportIP 53 mask 16 forward
  configure policy rule 4 udpdestportIP 67 mask 16 forward
  configure policy rule 4 ether 0x0806 mask 16 forward
  configure policy captive-portal listening 80
  configure policy captive-portal listening 443

Enable 'External Portal Enforcement' and 'Role by Switch Role' in PacketFence
switch configuration. Set 'registration' role to 'Unregistered'.

Use 'Extreme EXOS' switch type for this feature.

===== RADIUS authentication for CLI access

Configure RADIUS server IP as primary server and switch IP as client-ip. Specify
correct virtual router:

  configure radius mgmt-access primary server <SERVER_IP> 1815 client-ip <CLIENT_IP> vr <VR>

Configure the RADIUS shared-secret

  configure radius mgmt-access primary shared-secret <SHARED_SECRET>

Enable RADIUS for management access

  enable radius mgmt-access


==== Extreme VOSS / Fabric Engine (VSP series)

Use the _Extreme Networks VOSS / Fabric Engine_ switch type (module
`pf::Switch::Extreme::VOSS`) for the switches running VOSS or Fabric Engine. It
supports:

[options="compact"]
* 802.1X (EAP) and MAC authentication (NEAP) on wired ports
* VLAN assignment (`Extreme-Dynamic-Client-Assignments`, VOSS 8.8 and later)
  or Fabric Attach VLAN:I-SID assignment (`Fabric-Attach-VLAN-ISID`)
* DHCP Snooping, Dynamic ARP Inspection, IP Source Guard and the other
  `Extreme-Dynamic-Config` features per role, and any other additional
  attribute per role, with _Role by Access List_
* RADIUS Disconnect-Request to re-evaluate the access of an endpoint
* port bounce with a RADIUS CoA-Request (`Extreme-Dynamic-Config = PORTBOUNCE`, VOSS 8.10 and later)

The switch type returns these Access-Accept attributes:

[options="header",cols="1,3"]
|===
|PacketFence setting of the switch |Attributes
|_Role by VLAN ID_ |`Extreme-Dynamic-Client-Assignments = pv=<VLAN>,ev=0` (the endpoint in the VLAN, untagged)
|_Role by Switch Role_ |`Fabric-Attach-VLAN-ISID = <role value>`
|_Role by Access List_ |the lines of the role, see <<_additional_attributes_per_role,Additional attributes per role>>
|===

PacketFence ships the `Extreme-Dynamic-Config` (vendor 1916, attribute 252),
`Extreme-Dynamic-MHSA` (250), `Extreme-Dynamic-ACL` (251) and
`Extreme-Dynamic-Client-Assignments` (253) attributes in
[filename]`/usr/local/pf/raddb/dictionary.extreme`. The Fabric Attach attributes
(`Fabric-Attach-VLAN-ISID` 171, `Fabric-Attach-VLAN-Create` 170,
`Fabric-Attach-VLAN-PVID` 172, vendor 562) come from the FreeRADIUS dictionary;
the Extreme examples name the attribute 171 `Fabric-Attach-ISID`.

NOTE: The commands below follow the VOSS and Fabric Engine user guides. Their
options change between releases: check them against the CLI reference of the
release running on the switch. In the examples, PacketFence is 192.168.1.5 and
the switch is 10.0.0.8.

===== RADIUS servers and dynamic authorization

PacketFence is the RADIUS server of the EAP and NEAP authentications:

  radius server host 192.168.1.5 key useStrongerSecret used-by eapol
  radius enable

PacketFence needs the RADIUS accounting of the switch to close the
locationlog entries of the endpoints that leave a port. Check how accounting is
enabled for EAPoL (`acct-enable` of `radius server host`, `radius accounting
enable`) in the CLI reference of your release.

PacketFence sends a Disconnect-Request to re-evaluate the access of an endpoint
and a CoA-Request to bounce a port. Declare PacketFence as a dynamic
authorization client of the switch, and allow the requests on the
authentication ports:

  radius dynamic-server client 192.168.1.5 secret useStrongerSecret
  radius dynamic-server client 192.168.1.5 enable
  radius dynamic-server client 192.168.1.5 process-change-of-auth-requests
  radius dynamic-server client 192.168.1.5 process-disconnect-requests
  interface gigabitEthernet 1/1-1/24
  eapol radius-dynamic-server enable
  exit

PacketFence sends the requests to the UDP port 3799, unless the _Disconnect
port_ and _CoA port_ of the switch are set in PacketFence: set them if the
switch listens on another port.

===== 802.1X and MAC authentication in MHSA mode

Enable EAPoL globally, then on the ports. `eapol multihost
radius-non-eap-enable` adds the MAC authentication (NEAP) of the hosts that
don't speak 802.1X. MHSA (Multiple Host Single Authentication) is the mode
used by this switch type: once a host is authenticated, the other hosts of the
port use its authorization.

  eapol enable
  interface gigabitEthernet 1/1-1/24
  eapol status auto
  eapol multihost radius-non-eap-enable
  eapol multihost eap-oper-mode mhsa
  exit

Check the result with `show eapol port interface gigabitEthernet 1/1` and the
RADIUS server with `show radius reachability`. On an auto-sense port, `show
eapol port` can display `MHMV` in _Oper Mode_ while the port runs in Dynamic
MHSA.

In PacketFence, set the _Port host mode_ of the switch to `multi-host` for
MHSA ports, or `multi-auth` for MHMV ports, where each host authenticates on
its own.

===== Fabric Attach and I-SID assignment

Enable _Role by Switch Role_ on the switch in PacketFence and set the role
values to the Fabric Attach binding of each role. PacketFence returns it in
`Fabric-Attach-VLAN-ISID`:

[options="compact"]
* `<vlan>:<i-sid>`, for example `20:10020`: the VLAN 20 bound to the I-SID 10020
  (Switched UNI)
* `0:<i-sid>`, for example `0:10020`: an untagged binding to the I-SID 10020.
  Use it on Flex UNI and auto-sense ports, which take the I-SID only.

Flex UNI and auto-sense ports take an I-SID, not a VLAN: without an I-SID
offset, they ignore the VLAN returned with _Role by VLAN ID_ and the switch logs
`EAP WARNING Ignore the radius vlan attribute on Flex UNI port 1/1 with
auto-isid-offset disabled`. Use _Role by Switch Role_ with `0:<i-sid>` values
on these ports, or configure an I-SID offset: the switch computes the I-SID as
the offset plus the VLAN returned by PacketFence (with an offset of 1000, the
VLAN 20 is the I-SID 1020):

  eapol auto-isid-offset 1000

Example of a Flex UNI port with Fabric Attach:

  interface gigabitEthernet 1/10
  flex-uni enable
  fa
  fa enable
  eapol status auto
  eapol multihost radius-non-eap-enable
  exit

Several VLAN:I-SID bindings for one endpoint (an access point with several
SSIDs, for example) are one `Fabric-Attach-VLAN-ISID` attribute per binding;
the switch creates all of them in MHSA mode only. Add the other bindings to the
access list of the role (see
<<_additional_attributes_per_role,Additional attributes per role>>):

  Fabric-Attach-VLAN-ISID = 30:10030

`Fabric-Attach-VLAN-Create` and `Fabric-Attach-VLAN-PVID` are added the same
way, when the switch must create the VLAN of a binding or set the PVID of the
port.

===== Extreme-Dynamic-Client-Assignments

`Extreme-Dynamic-Client-Assignments` (vendor 1916, attribute 253, string)
assigns the endpoint to an existing VLAN or I-SID and can also create the VLAN
or private VLAN, with its name, its I-SID and the I-SID name. PacketFence
returns `pv=<VLAN>,ev=0` with _Role by VLAN ID_. For the other options, put the
attribute in the access list of the role and leave the role out of _Role by VLAN
ID_, otherwise the endpoint gets two assignments. The value is a list of
options separated with `,`:

  create=vlan|pvlan,pv=<primary VLAN>,sv=<secondary VLAN>,vni=<I-SID>,ev=<egress tag>,vn=<VLAN name>,vnin=<I-SID name>,mvni=<I-SID>

[options="header",cols="1,3"]
|===
|Option |Use
|`create` |`vlan` creates a platform VLAN, `pvlan` a private VLAN. Without it, the VLAN must exist. Ignored on DvR leafs.
|`pv` |platform VLAN of the endpoint, required (the attribute is ignored without it)
|`sv` |secondary VLAN, with `create=pvlan` only
|`vni` |I-SID: without `create`, with `ev`, the Switched UNI of a Flex UNI port; with `create`, the I-SID of the new VLAN
|`ev` |egress tag: `0` or `U` untagged (default), `T` tagged with `pv`; on a Flex UNI port, the C-VID of the Switched UNI
|`vn`, `vnin` |VLAN name and I-SID name, with `create` only
|`mvni` |I-SID of the Layer 3 VSN VLAN, enables IP Multicast config-lite (SPB multicast) on the VLAN
|===

Without `create`, the options match the standard and Fabric Attach attributes:

[options="header",cols="1,2,2"]
|===
|Port |Attributes |Extreme-Dynamic-Client-Assignments
|regular |`Tunnel-Private-Group-Id = 20` |`pv=20`
|regular |`Tunnel-Private-Group-Id` and `Egress-VLANID` |`pv=20,ev=0` (untagged) or `pv=20,ev=T` (tagged)
|Flex UNI |`Fabric-Attach-VLAN-ISID = 0:10020` |`vni=10020,ev=0` (untagged; a VLAN ID in `ev` for a tagged Switched UNI)
|Flex UNI |`Tunnel-Private-Group-Id` with `eapol auto-isid-offset` |`pv=20,ev=0`
|===

Egress VLAN names are not supported. The VLANs and I-SID names created by the
attribute exist as long as EAP clients use them: they are deleted with the last
client and are not saved in the configuration. A created VLAN can't have static
settings, uses the MSTP instance 0, and private VLANs are supported on Flex UNI
ports only. In MHMV mode, only the last assignment of a session is applied.
DHCP Snooping, Dynamic ARP Inspection and IGMP Snooping of these VLANs are
enabled with `Extreme-Dynamic-Config`.

Example of an access list line that creates the VLAN 30 with the I-SID 10030
for the guests:

  Extreme-Dynamic-Client-Assignments = create=vlan,pv=30,vni=10030,ev=0,vn=Guest,vnin=Guest

===== Port bounce

PacketFence bounces a port with a CoA-Request carrying
`Extreme-Dynamic-Config = PORTBOUNCE` (VOSS 8.10 and later), for example from
_Restart switchport_ on a node in the admin interface. The EAP sessions of the
port are kept, Power over Ethernet included if the port supports it, and the
endpoint renews its DHCP lease in the VLAN or I-SID assigned by PacketFence.
The interface state shown by the switch tells when a port is down because of a
RADIUS port bounce.

`PORTBOUNCE` can also be returned in the Access-Accept, in the access list of a
role, so that the endpoints renew their address after a change of VLAN,
for example a PC behind a phone that reboots.
The switch doesn't bounce the port again at the periodic re-authentications.
On Fabric Engine 9.3.1.0, a Disconnect-Request carrying `PORTBOUNCE` doesn't
clear the NEAP session: PacketFence sends it in a CoA-Request only.

===== DHCP Snooping, Dynamic ARP Inspection and IP Source Guard

The `Extreme-Dynamic-Config` attribute (vendor 1916, attribute 252, string;
the Extreme documentation also names it `Extreme-Dyn-Config`) of the
Access-Accept configures VLAN and port features for the endpoint:

[options="header",cols="1,3"]
|===
|Value |Feature
|`DHCPSNOOP` |DHCP Snooping on the VLAN returned by RADIUS (Flex UNI port: the platform VLAN of the returned I-SID)
|`DAI` |Dynamic ARP Inspection on the VLAN returned by RADIUS (Flex UNI port: the platform VLAN of the returned I-SID)
|`IGMPSNOOP` |IGMP Snooping on the VLAN returned by RADIUS (Flex UNI port: the platform VLAN of the returned I-SID)
|`IPSG` |IP Source Guard on the port
|`BPDU` |BPDU Guard on the port
|`SLPPGUARD` or `SLPPGUARD:<seconds>` |SLPP Guard on the port; the port is enabled again after the timer (default 60 seconds)
|`REAUTH` or `REAUTH:<seconds>` |EAPoL re-authentication of the port (EAP and NEAP), with its period
|`PORTBOUNCE` |port bounce, Power over Ethernet included (VOSS 8.10 and later)
|`WOL` |EAP traffic control (Wake on LAN) on the port
|`AN-ADVERTISMENTS:<speed>` |custom auto-negotiation advertisements (CANA) of the port, for example `AN-ADVERTISMENTS:100Half` or `AN-ADVERTISMENTS:100H`; the speeds are `10Half`, `100Half`, `100Full` and `1000Full`
|===

When no VLAN or I-SID is returned, `DHCPSNOOP` and `DAI` apply to the default
VLAN of the port (Flex UNI port: the platform VLAN of the untagged I-SID).
When a VLAN or I-SID is returned, they also apply to the default VLAN, to
prepare IP Source Guard, but only if `IPSG` is returned too.

With `REAUTH`, a NEAP session (silent devices) is no longer removed when its
MAC address ages out, only by an administrator or a RADIUS reject or timeout.
A re-authentication period of 0 keeps the EAP and NEAP sessions from aging out,
which is a security risk. The `Session-Timeout` of a session changes its own
re-authentication period, when re-authentication is enabled on the port.

IP Source Guard needs DHCP Snooping and Dynamic ARP Inspection on all the
VLANs of the port. Without them, the switch doesn't apply `IPSG` and logs
`EAP WARNING Cannot apply Radius IP Source Guard attribute on port 1/15 without DHCP Snooping and DAI attributes`.
PacketFence doesn't return `IPSG` without `DHCPSNOOP` and `DAI`, and logs a
warning.

[[_additional_attributes_per_role]]
===== Additional attributes per role

The switch takes one value per attribute: several features are several
`Extreme-Dynamic-Config` attributes in the same Access-Accept. Enable _Role by
Access List_ on the switch (or its group) in PacketFence and write, in the
access list of each role, one attribute per line, in the format
`Attribute-Name = value`:

  Extreme-Dynamic-Config = DHCPSNOOP
  Extreme-Dynamic-Config = DAI
  Extreme-Dynamic-Config = IPSG

PacketFence returns each line as one attribute, after the VLAN and the Fabric
Attach binding of the role. The lines can carry any attribute of the RADIUS
dictionary: `Extreme-Dynamic-Config` features (`BPDU`, `REAUTH:3600`,
`PORTBOUNCE`, ...), more `Fabric-Attach-VLAN-ISID` bindings,
`Fabric-Attach-VLAN-Create`, `Extreme-Dynamic-Client-Assignments`. Empty lines,
lines starting with `#` and lines of another format, such as ACLs, are ignored,
as well as attributes that are not in the RADIUS dictionary (with a warning in
the logs). The access lists of the roles (_Roles_ configuration) are not used
by this switch type.

The roles without lines get no feature: for example, give the devices with a
static IP address a role without `DHCPSNOOP`, `DAI` and `IPSG`. RADIUS filters
can still add attributes or replace the answer, by switch or any other
condition.

Before enabling the features, trust the ports that receive the DHCP replies and
the ARP traffic of the infrastructure: the port of the DHCP server or relay, the
port of the PacketFence server and the uplinks. In a fabric, check how the NNI
ports are handled by DHCP Snooping on your release. Mark the same ports as
trusted for Dynamic ARP Inspection (see the CLI reference of your release).

  interface gigabitEthernet 1/48
  ip dhcp-snooping trusted
  exit

[options="compact"]
* The devices with a static IP address have no DHCP Snooping binding: Dynamic
  ARP Inspection drops their ARP packets and IP Source Guard their traffic. Add
  a static binding for each one, or give them a role without the features.
* A port can be error-disabled when it receives more DHCP or ARP packets than
  allowed. Check the rate limits of your release before enabling the features
  on ports with many hosts (access points, MHSA ports behind a hub).
* PacketFence is the DHCP server of the registration and isolation networks.
  Trust the port that leads to PacketFence (or to the DHCP relay that forwards
  to it), otherwise the switch drops its DHCP replies and the endpoints in
  these networks get no address. DHCP Snooping doesn't support option 82.
* IP Source Guard works on the DHCP Snooping and Dynamic ARP Inspection
  untrusted ports. It filters on the addresses learned on the port.

The same features can be configured statically, for the VLANs that don't come
from RADIUS:

  ip dhcp-snooping enable
  interface vlan 20
  ip dhcp-snooping enable
  ip arp-inspection enable
  exit
  interface gigabitEthernet 1/1
  ip source verify enable
  exit

===== MHSA and MHMV

Fabric Attach attributes:

[options="header",cols="2,2,2"]
|===
|Attribute |MHSA |MHMV
|`Fabric-Attach-VLAN-ISID` with several bindings |all the bindings are created (up to 94) |only the last binding is created
|`Fabric-Attach-VLAN-PVID` |processed |not processed
|===

VLANs on which `DHCPSNOOP` and `DAI` are enabled, and `IPSG` when it is
returned with them:

[options="header",cols="1,1,1,1,3"]
|===
|Mode |`IPSG` returned |Flex UNI |VLAN or I-SID returned |Enabled on
|MHSA |yes |yes |yes |all the platform VLANs of the port (with IPSG)
|MHSA |yes |yes |no |all the platform VLANs of the port (with IPSG)
|MHSA |yes |no |yes |all the platform VLANs of the port (with IPSG)
|MHSA |yes |no |no |all the platform VLANs of the port (with IPSG)
|MHSA |no |yes |yes |the platform VLANs of the returned I-SIDs
|MHSA |no |yes |no |all the static platform VLANs
|MHSA |no |no |yes |the returned VLAN
|MHSA |no |no |no |the default VLAN
|MHMV |yes |yes |yes |the platform VLANs of the returned I-SID and of the untagged I-SID (with IPSG)
|MHMV |yes |yes |no |the platform VLAN of the untagged I-SID (with IPSG)
|MHMV |yes |no |yes |the returned VLAN and the default VLAN (with IPSG)
|MHMV |yes |no |no |the default VLAN (with IPSG)
|MHMV |no |yes |yes |the platform VLAN of the returned I-SID
|MHMV |no |yes |no |the platform VLAN of the untagged I-SID
|MHMV |no |no |yes |the returned VLAN
|MHMV |no |no |no |the default VLAN
|===

When no VLAN, and no platform VLAN of the returned I-SID, exists, they are
enabled on the default VLAN or on the platform VLAN of the static untagged
I-SID.

MHMA is a mode of the ERS switches; VOSS offers MHSA and MHMV only. The
Fabric Attach attributes don't work in MHMA.

===== PacketFence configuration

In _Configuration -> Policies and Access Control -> Switches_, add the switch
with:

[options="compact"]
* _Type_: Extreme Networks VOSS / Fabric Engine
* _Mode_: production
* _Deauthentication Method_: RADIUS
* _Port host mode_: `multi-host` (MHSA ports)
* _RADIUS secret_: useStrongerSecret
* _Role by VLAN ID_ (VLAN ports, VOSS 8.8 and later) or _Role by Switch Role_
  with VLAN:I-SID values (Fabric Attach, Flex UNI and auto-sense ports)
* _Role by Access List_ for the DHCP Snooping, Dynamic ARP Inspection and IP
  Source Guard features, and the other additional attributes, per role
